考心晴缺少"先收纳、后处理"担忧的环节。请新增"担忧收纳盒"：随手写下担忧，之后选择放下，或把它变成一条待办。

场景1：收纳一条担忧。在"我的"页面的功能列表中新增入口"担忧收纳盒"，入口说明文字中包含"X 条待处理"（X 为当前待处理担忧数量，初始为"0 条待处理"）。点击进入标题为"担忧收纳盒"的页面，顶部有一个单行文本输入框（占位提示"写下此刻的担忧"）和按钮"放进盒子"，页面中只有这一个输入框。页面上始终显示统计文字，格式严格为"待处理 a · 已放下 b · 已转待办 c"（半角空格和中点"·"），初始为"待处理 0 · 已放下 0 · 已转待办 0"。盒子为空时显示"盒子里还没有担忧"。输入为空或只有空格时点击"放进盒子"不新增任何条目；内容最长 40 字。输入"担心英语听力听不懂"并点击"放进盒子"后：输入框清空，该担忧出现在"待处理"分组中，空状态提示消失，统计变为"待处理 1 · 已放下 0 · 已转待办 0"。返回"我的"页面后，入口说明显示"1 条待处理"。

场景2：放下一条担忧。只有待处理的担忧带有两个按钮"放下"和"转为待办"。点击某条担忧的"放下"后，它从"待处理"分组移到标题为"已放下"的分组，统计中"待处理"减 1、"已放下"加 1；返回"我的"页面后入口计数同步减少。

场景3：把担忧转为待办。点击某条待处理担忧的"转为待办"后，它移到标题为"已转待办"的分组，统计中"已转待办"加 1、"待处理"减 1；同时以与担忧完全相同的文字为标题，在"考试与计划"页面的待办列表中新增一条未完成、非重点的待办。从"我的 → 目标与计划"进入"考试与计划"页面可看到它。

场景4：数据保留与清理。完全退出并重启应用后，担忧文字、所属分组、统计和入口计数与退出前一致。"已放下"和"已转待办"分组中的每条担忧带有"删除"按钮（待处理的担忧没有），点击后该条立即消失、统计相应减少；删除一条"已转待办"的担忧不会删除已生成的待办。

约束：不得破坏已有功能；数据需本地持久化；沿用应用现有的页面风格与返回方式。
